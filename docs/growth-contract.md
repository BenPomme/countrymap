## Common interfaces
- New src/lib/analytics/events.ts exports trackEvent(name: string, params?: Record<string,string|number|boolean|undefined>): void. Consent denied/unknown means no transmission. Allowlist event and parameter names. Permitted events: game_start, game_complete, share_intent, share_handoff, share_copy, share_cancel, share_error, referral_open, referral_game_complete, affiliate_click, reward_mint, reward_copy, checkout_start, checkout_return, purchase, reminder_toggle. No UID, email, code, full URL, query or arbitrary text parameters. Parameters include game, puzzle_day, content_id, placement, method, score, correct, partner, status, value, currency, transaction_id only as appropriate and sanitized. Backend purchase data must be verified, never inferred from a URL. Existing GA4 / Ads ids remain; preview is denied by default. Strip private query strings from analytics page location and referrer.
- Common styling: class names twt-shell, twt-container, twt-display, twt-panel, twt-button, twt-button-secondary, twt-kicker, twt-prose. SiteHeader and SiteFooter are default exports under src/components/site, no props required, mounted once by root layout. Main page content is left aligned, generous space and clear hierarchy; no grid of identical promo cards. Colors: paper #fff9e8, ink #192947, blue #294cc4, yellow #ffda62, coral #dc654e, green #246e55; validate contrast and use blue for primary actions. Bricolage Grotesque display and Source Sans 3 body if local licensed font files can be added; honest system fallback otherwise. No external runtime font requirement. Maps and a single bold editorial fact are the distinctive element.
- Shared referral URL /challenge/?game=truthle|true-false&day=YYYY-MM-DD&code=optional. Treat code as untrusted; never send code to analytics. Old day shows expired-round explanation and offers today's game; no invented archive play. All supported share formats include canonical destination and actual expiry when a gift exists. Map URLs use existing /map/<slug>/ with supported filter query params; discoveries use x/y metric identifiers, validated against catalogue.
- New src/lib/truthle/gifts.ts (owned by rewards worker) exports buildChallengeUrl({game,day,code?}), rememberChallenge({game,day,code?}), getRememberedChallenge(game), clearRememberedChallenge(game). local/session storage must be defensive and not put code into tracking. Anonymous auth remains supported. Game worker can use these helpers to preserve gift context, or read the same session contract documented by rewards worker.
- Backend: createTruthleRetryCheckout accepts existing quantity/returnTo and optional shareCode; validate code server-side before applying, restrict a gift to one attempt, reject same issuer UID and expired/redeemed/wrong product. Existing valid codes remain supported through in-app entry. Add getTruthleCheckoutStatus({sessionId}) -> {status:'pending'|'fulfilled'|'expired'|'failed',credits:number}; authenticate owner, verify Stripe/session/grant, never trust query strings. consumeTruthleRetry accepts {requestId} (stable per attempted consumption, reuse on transport retries); returns existing success/remainingRetries shape, repeat same request returns same result without another debit. Do not break existing non-UI clients silently; document explicit compatibility and safe legacy behavior.
- Frontend storage.ts owned by games worker: align callable payloads, verified checkout polling and consume request id. Backend worker owns functions/** and firestore.rules exclusively. Server helpers can be extracted into functions/lib with node:test pure/mocked tests and rules emulator checks. No production secrets, API calls, purchases or minted codes in tests.
